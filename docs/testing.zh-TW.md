## 自動檢查

完成[開發環境設定](development/README.zh-TW.md)後，在儲存庫根目錄執行：

```sh
npm run build
npm test
npm run check:architecture
cargo test --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
cargo test --locked --manifest-path native/transport/Cargo.toml
cargo test --locked --manifest-path native/transport/Cargo.toml -p corelib device::xiaomi::sar::tests
npm run build:desktop
```

執行時與手環測試使用注入的時鐘、傳輸及平台適配器。契約測試覆蓋啟動、設定恢復、異步圖像、首次引導與協議相容；架構檢查執行[架構指南](architecture/README.zh-TW.md)的所有權邊界。

PR 僅檢查原始碼，不生成發佈包。發佈構建額外驗證兩種 Mac 架構、包內容、簽名完整性及歸檔移動後執行。結果見 [GitHub Actions](https://github.com/JamesGZM/miband-agent-buddy/actions)。

## 設備覆蓋

| 環境 | 覆蓋範圍 |
| --- | --- |
| Apple Silicon macOS | 本地構建、桌面 UI 與設備連線檢查 |
| Intel macOS | CI 發佈構建和歸檔驗證；仍需實機手環測試 |
| 小米手環 9 NFC 版 | 韌體 3.1.32 的帳號連線、Buddy 安裝、活動同步與短時喚醒 |
| 小米手環 9 標準版 | 應用的目標設備，尚需實機確認 |

已在 NFC 版驗證 Buddy 0.5.5 安裝與軟體通信。實際幀率、耗電和持續亮屏可靠性仍未確認。

本地亮屏修復增加了採樣拋錯／卡住時繼續續期、過期資源顯示未知、無重疊採樣、停止後忽略遲到結果，以及亮度負值回執和超時重試測試。它們是軟體證據，不代表長時間實機驗收完成。

## 手工驗收

盡可能使用測試帳號與設備。不要為了測試引導而清除已有帳號或配對。

1. 沒有保存帳號時啟動，檢查歡迎入口、服務地區、設備選擇與配對說明。
2. 有保存設備時重啟，確認主題與設定恢復，預覽不閃爍，也不重複首次引導。
3. 圖像未緩存時切換主題，確認完整畫面替換，沒有空白或混合圖層。
4. 檢查手環頁面中未安裝、已安裝、已更新狀態，分別判斷傳輸完成與安裝確認。
5. 在活動同步開啟和關閉時測試手動喚醒與設定，同時觀察真實螢幕和 App 回報。
6. 執行重疊 AI 任務；一個結束不影響另一個，最後一個結束後才開始待機倒數。
7. 檢查省電、斷線恢復、關閉視窗和退出，測試後恢復原設定。
8. 開啟任務亮屏後，持續觀察超過以往熄屏時間，記錄熄屏時任務、連線、最後同步時間與亮屏診斷。分別驗證長時間思考、工具執行、等待確認、最終結束及停止同步後的本地釋放。

## 當前限制

- 不同韌體的藍牙恢復與長期任務亮屏仍需驗證。已測試韌體可能意外結束長時間亮屏；API 成功不代表物理螢幕亮著。
- 手環安裝可能完成，但最終結果未傳回 Mac。先重連、檢查執行版本，再決定是否重裝。
- 動畫更新頻率是調度目標，尚未測量面板實際幀率與功耗。
- GitHub macOS 包使用無證書 ad-hoc 簽章，未經 Apple 公證，首次打開可能需要標準批准流程。
- AI 接入依賴工具提供的生命週期事件，主題名稱不代表該產品存在原生 Hooks API。

可重現問題通過[支援指南](../SUPPORT.zh-TW.md)報告。公開報告不要包含帳號、設備密鑰、提示詞或對話。

在小米手環 9 NFC 韌體 3.1.32 上，使用者確認從手動亮度 202 降至省電 25 時能明顯看到變暗。原生讀回與 App 已驗證自動開關、停用手動控制、模式恢復及手動值保留。安裝前先讓有回應的舊頁面退出，後續本地更新已自動恢復同步。這是短時實機檢查，不代表續航測量或證明韌體唯一根因。使用者還確認，拔下後重新連接充電器時，充電狀態更新加快，Buddy 無需手動開啟即可自行恢復。執行階段容忍一次臨時狀態探測失敗，結合裝置事件與約 5–6 秒輪詢兜底。這次短時恢復檢查不代表藍牙始終沒有中斷。低電量系統通知顯示仍需系統驗證；門檻和去重測試不能證明 macOS 已顯示通知。

2026-11-12，本地 App、隨包 Node 和傳輸程式已使用已有 Apple Development 證書及各自固定識別簽名。兩個內容不同的測試二進位檔產生相同的證書 designated requirement。新身分授權一次後，使用者確認重啟同一份 App 沒有再次彈窗並恢復連線，隨後實際手動喚醒操作取得匹配亮屏回執。重啟後的這次短時檢查未出現 ACK 逾時或傳輸關閉。CI 模式選擇已由本地測試驗證，沒有發布新 GitHub 版本；不代表已驗證未來漏回執時的實機自動恢復，或所有 macOS 版本的跨建置權限保留。

本地啟動準備恢復修復：328 項 Node 測試通過，覆蓋無需新 Hook 的重連恢復、有次數限制的準備重試及首次查詢優先級。使用者已確認觀察 2–3 分鐘時持續亮屏，並進行五分鐘本地健康紀錄觀察。這仍不代表真實無線中斷後的自動恢復或長時間耐久已獲實機驗證。
