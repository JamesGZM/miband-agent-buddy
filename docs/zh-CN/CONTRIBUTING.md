# 参与 MiBand Agent Buddy

[English](../../CONTRIBUTING.md) · **简体中文** · [繁體中文](../zh-TW/CONTRIBUTING.md)

欢迎提交问题报告、设备测试、翻译、文档和代码。本指南说明如何准备便于审查的改动。

## 开始之前

- 使用问题请先阅读[支持指南](SUPPORT.md)；安全漏洞通过[安全说明](SECURITY.md)中的私密渠道报告。
- 提问前搜索[已有 Issues](https://github.com/JamesGZM/miband-agent-buddy/issues)，使用模板描述复现步骤或功能要解决的问题。
- 大型功能、新设备支持和架构调整请先开 Issue 讨论。小修复与文档更正可以直接提交 PR。

Issues 和 PR 均欢迎使用英文、简体中文或繁体中文。

## 开发环境

Fork 仓库，从 `main` 建立分支，按照[开发指南](development/README.md)准备 macOS 依赖、构建环境并了解目录结构与验证命令。

每个 PR 聚焦一个问题。避免混入无关格式调整、生成文件或重构。修复行为问题时增加回归测试；影响用户或贡献者时同步更新文档。

## 工程规则

- 桌面外观、手环主题与 AI 活动分别管理。
- 手环界面优先使用代码绘制，保留已确认的 Buddy 设计。图片资源、动画开销及实机验证遵循[快应用界面指南](development/quickapp-ui.md)。
- 遵守[架构边界](architecture/README.md)。平台访问放在适配器中，共享协议与显示模块保持纯函数。
- 在进程和应用边界校验输入；协议变化需一起更新所有消费者及合成测试数据。
- 测试通过注入时钟和依赖控制行为。操作结束时取消定时器、监听器与子进程，忽略旧会话回调。
- 修改源生成器，不手改生成资源。上游修改使用独立补丁并保留署名，不直接修改下载或 vendored 的源文件。
- UI 文案集中在语言目录中，三种语言同步更新，并保留键盘操作、进度和错误反馈。
- 添加网络服务、分析或遥测前先提出方案。源码、测试和诊断不得包含凭据、提示词、对话、设备密钥及个人标识。

重要的所有权或协议决策需在 `docs/zh-CN/architecture/` 添加简短 ADR，说明问题、决策、替代方案、兼容性与证据。供编码助手执行的规则原文见 [AGENTS.md](../../AGENTS.md)。

## 验证

开发时先运行最小相关测试。提交代码前运行：

```sh
npm test
npm run check:architecture
```

按[开发指南](development/README.md#验证)运行受影响的 Rust 测试与构建。UI 改动提供截图或简短录屏；设备改动说明型号、固件、操作和实际结果。没有设备时明确说明，构建或软件回执成功不代表物理屏幕已亮。

仅修改文档时，检查链接、命令和各语言版本的一致性。说明实际运行的检查。

## PR 内容

1. 用户看到的问题及修正后的行为。
2. 关键实现决策及取舍。
3. 自动测试、手工验证及尚未验证的条件。
4. 关联 Issue、兼容性和文档变化。

不要附加私密日志、凭据、带标识的账号截图、原始蓝牙数据或本地备份。构建产物、缓存、编辑器索引与 `.agent` 记录不进入公开源码。PR 模板只是起点，说明应对应实际改动。

维护者可能要求修改或拆分 PR。合并不代表立即发版；版本与发布遵循[发布流程](open-source/RELEASING.md)。

## 社区行为

尊重贡献者与用户，针对工作给出可执行的反馈，包容不同经验水平。禁止骚扰、歧视、威胁或公开他人私密信息。维护者可管理或关闭破坏性讨论；违反 GitHub 平台规则的行为可通过其举报工具处理。
