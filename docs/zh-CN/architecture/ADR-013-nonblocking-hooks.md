# ADR-013: 非阻塞观察 Hooks

[English](../../en/architecture/ADR-013-nonblocking-hooks.md) · **简体中文** · [繁體中文](../../zh-TW/architecture/ADR-013-nonblocking-hooks.md)

## 问题

同步命令会等待本地 HTTP，接收端无响应时约 600ms；错误放行不代表不等待。旧安装器也不会升级已匹配命令的同步字段。

## 决定

支持时使用原生 async。CLI 先脱敏，再启动忽略标准管道的独立发送进程；不等待 HTTP。输入上限 150ms，HTTP 600ms，发送进程 1.2 秒。Codex SessionEnd 只执行短入口。不重试、不存储原始输入。时间戳在读取输入与派发前生成；忽略较早事件，同毫秒终止状态优先。重装仅升级自有 async/timeout，保留备份、原子写入及其他设置。

## 替代方案

仅缩短超时仍会阻塞；无限后台进程会泄漏资源，继承管道会延长宿主等待。持久队列需要新增存储与生命周期契约。仅原生 async 无法覆盖 SessionEnd 和自定义 harness。

## 兼容性

保留兼容入口、库发送 API、会话哈希及三字段协议。尽力送达，宿主后台入口可能乱序或在退出时取消；发送时间不是宿主序号。较晚毫秒的新提示可重启会话。

## 证据

测试覆盖独立进程、关闭管道、非法与未结束输入、脱敏、配置升级、无副作用导入及乱序事件。进程启动仍有少量开销；宿主加载、信任和手环实物响应需单独观察。

## Cursor 本机兼容

本机 Cursor 入口通过可测试适配器使用相同的限时后台发送，保留 custom 命名空间、会话身份和既有命令路径。preToolUse 需要有效权限响应，空对象可能被当成格式错误；输入或启动失败时仍返回不拦截响应，不修改其他 Hooks 的决策。测试覆盖生命周期与隐私映射、派发失败、未结束输入和响应格式。
