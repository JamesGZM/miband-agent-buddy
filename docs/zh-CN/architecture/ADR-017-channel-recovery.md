# ADR-017: 通道生命周期与分层恢复

[English](../../en/architecture/ADR-017-channel-recovery.md) · **简体中文** · [繁體中文](../../zh-TW/architecture/ADR-017-channel-recovery.md)

## 问题

系统蓝牙仍连接时，Buddy 可能返回首页，或 interconnect/RFCOMM 会话不再响应。后续 ACK 超时以前会覆盖首次异常。

## 决定

Vela 负责建立通道。注入的手环控制器监听 onopen/onclose/onerror，在创建和打开时按能力调用 getReadyState，并设置一秒本地期限。只保留一份最新 ACK；关闭或错误后，下次打开最多补送一次，重复打开不会累积队列。启动时尚未就绪不算异常。销毁会退役定时器、监听器及回调。可选 channelLifecycle 能力与 ACK 只携带有界计数、时间、枚举和数字错误码，不携带平台原始错误文本。

Mac 在应用 ACK 缺失后立即探测设备。探测成功只允许现有的、有界且用户已启用的活动任务 Buddy 恢复，不重建传输。连续两次探测失败，或原生通道/子进程退出，才进入现有有界退避重连。应用、设备探测、子进程恢复分别记录；探测失败本身不能证明物理蓝牙断开。暂停、任务结束、断开、安装和旧代回调继续遵守取消规则。

诊断在自动重连后保留首个观测异常的主机时间、层级、安全错误码和子进程代数，并仅补记一次原子进程退出码/信号。按能力接收的通道证据另保留手环本地首个事件时间与码。后续成功或 ACK 超时不能覆盖首次异常。明确连接操作开启新的观测窗口；runtime/App 重启也会开启新窗口。健康文件逐字段白名单投影。

首次 ACK 超时允许一次快速新快照重试；持续空闲失败保留正常 30 秒投递退避。第一次探测失败后先给新快照回复机会，再做第二次探测。探测请求 ID 唯一，迟到结果不能结算新的探测。明确用户操作优先于后台探测。

## 替代方案

ACK 丢失就重置全部蓝牙会打断健康通道。虚构重连 API、周期性重开应用及伪造后台能力均不采用。将启动建链算成异常会遮住真正的首个故障。

## 兼容与证据

v1 协议及 session/seq 匹配不变，无能力字段的旧 ACK 继续有效。缓存 ACK 补送不会重新应用快照或延长亮屏租约。共享夹具、假时钟生命周期/恢复测试及 Rust 投影测试覆盖期限、旧回调、隐私过滤和首因保留。编译或 ACK 不能证明实物退出、重启、长期掉线的原因或已解决。
