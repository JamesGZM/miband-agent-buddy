# 快应用界面开发

[English](../../en/development/quickapp-ui.md) · **简体中文** · [繁體中文](../../zh-TW/development/quickapp-ui.md)

Buddy 手环界面应尽可能使用代码绘制。更换绘制方式时，保留已确认的角色、胶囊外框、资源布局和交互。绘图原型用于验证设备能力，不代表另做一套产品设计。相关边界见[开发指南](README.md)、[架构](../architecture/README.md)与[绘制决策](../architecture/ADR-008-animation-and-task-rings.md)。

## 代码与图片原则

现有界面使用原生 `div`、`text` 和弧形 `progress`，与桌面预览共享几何和动画计算。这些组件已经过目标手环实测；不要假定 Vela 支持浏览器 Canvas API。能力查询 API 缺失表示支持情况未知，不等于组件不受支持。

| 资源 | 项目规则 |
| --- | --- |
| 角色、外框、资源环和动画 | 使用代码生成几何，不恢复 PNG 逐帧动画或整屏界面图片。 |
| 手环应用入口图标 | 保留必需的 `common/icon.png`，由已确认的母图生成，与内页绘制分开。 |
| 桌面主题缩略图 | 三张生成的缩略图仅供 Mac 使用，不进入手环 RPK。 |
| 后续确有位图需求 | 说明原生绘制不适合的原因，控制尺寸和数量，测量包体、解码后内存及实机表现。 |

当前构建会检查 RPK，仅允许入口图标这一张图片。若确需改变资源原则，必须同时更新检查与文档。压缩文件小不代表解码内存及缓存开销小；代码绘制也有成本，节点、观察器或逐帧分配过多同样可能卡顿。性能收益需要用实际负载比较。

## 源码职责

| 源文件 | 修改内容 |
| --- | --- |
| `packages/buddy-shared/presentation/geometry.js` | 统一的 490×192 布局、角色、胶囊路径及原生 192×490 坐标投影；保持纯 ES5 CommonJS。 |
| `packages/buddy-shared/presentation/native-ui.js` | 共享动画时间与有效帧率策略。 |
| `apps/band/src/controllers/page-controller.js` | 注入平台 API、更新观察数据，以及页面和定时器生命周期。 |
| `apps/band/src/pages/index/index.ux` | 原生模板、样式和文字布局。 |
| `apps/desktop/ui/preview.js` | 使用相同原生几何与时间的 Canvas 预览。 |
| `scripts/prepare_shared.py` | 从统一共享模块生成 Vela／浏览器适配文件。 |
| `scripts/render_band_ui.py` | 三张桌面缩略图及已知废弃帧目录的清理。 |
| `scripts/prepare_band_icon.py` | 从 `apps/desktop/artwork/app-icon.png` 生成入口图标。 |

修改源文件和生成器后重新构建，不手改暂存的应用副本或生成资源。废弃资源由对应生成器清理，不顺手删除其他本地文件。

## 动画与重绘开销

多 AI 状态计算属于 Mac：聚合会话、选择优先级／模式并编译有序配色后再发送快照。支持的新手环收到 `activityRing`，不接收聚合输入，只应用方案并播放本地动画。兼容旧主机时每次快照转换一次计数，不逐帧转换；保留本地断线回退和亮屏看门狗（[ADR-009](../architecture/ADR-009-host-activity-display.md)）。

- 保持观察数组和图形 ID 稳定，仅原地更新变化字段；缓存不变的角色几何，通过单个数值偏移移动整组，避免每帧重建所有绑定对象。与 UI 无关的数据不要放进观察模型，参考官方[内存优化](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/memory.html)。
- 每个绘制器只缓存当前任务配色布局和最多 33 行小型色阶数据；任务数、主题或状态变化时使缓存失效。移动高光的每段复用固定的矩形／圆弧节点。绘制耗时计入帧预算，不在绘制后再等待完整间隔。这些措施减少重复计算和组件增删，保留 loading 效果，也不通过蓝牙逐帧传图；实机流畅度仍需测量。
- 控制组件数量、嵌套和动态样式，参考官方[业务优化](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/business.html)。资源显示值不变时跳过几何更新；页面隐藏时停止动画，销毁时取消所属定时器和监听器。
- 固定背景和填充的层级。Vela [stack](https://iot.mi.com/vela/quickapp/zh/components/container/stack.html) 的后置直接子组件覆盖前面的组件；底轨应放在固定背景容器，避免动态子节点盖住进度线。
- 保留先投影到原生坐标、再绑定图形的实现。实机出现 CPU 弧线累积缺口后，已移除图形父容器旋转。直线／曲线接点与运动端点都要实测，几何单元测试不能证明固件重绘正确。

已采用的内存优化：诊断计数与资源插值状态保留在控制器闭包，不放入响应式页面模型。只有常量资源标签使用 `static`，数值、图形和颜色仍保持动态。颜色缓存直接比较有界列表，不逐帧拼接字符串键。亮度接口只在前台切换或设置变化时调用，不进入动画计时器。不要定时执行 `runGC`：官方内存文档明确指出频繁 GC 会造成卡顿。

`buddyFps` 为 10–30 的整数，默认 10，使用数字输入框，通过保存或 Enter 提交。省电模式固定有效帧率为 10，并保留原选择。桌面预览使用相同几何与有效帧率，以新鲜 ACK 时间对齐动画阶段。预览是场景重建，不是手环截图；字体与栅格化差异仍需目测对比。

设置值及 ACK 的 `drawing.effectiveFps` 仅表示调度目标，JavaScript 帧计数也不等于面板实际刷新帧率。持续运行上限及耗电尚未测量，30 FPS 是测试目标，不是性能保证。

## 构建与实机验证

在仓库根目录构建手环资源，运行相关几何、控制器和预览测试，再执行公共检查：

```sh
npm run build
node --test tests/band/code-probe.test.mjs tests/band/native-ui.test.mjs tests/contracts/preview-animation.test.mjs
npm test
npm run check:architecture
```

预览或随包 RPK 改变后重新构建桌面包；本地测试版本见[开发指南](README.md)。构建不代表安装或发布。修改资源生成方式时，记录 RPK 字节数和图片清单。

实机需检查两页、所有主题／活动状态、跨越直线与曲线接点的资源值、连续百分比变化、隐藏／返回与重复前台启动。验证省电及帧率选择恢复，再分别观察持续任务和任务结束后的熄屏延迟。记录型号、固件、时长与物理结果；传输成功或 ACK 不能证明绘制、稳定性或亮屏。

在 Smart Band 9 NFC 固件 3.1.32 上，用户报告本地 code.3 卡死并重启；该版以 30 Hz 替换观察数组，观察器／渲染压力是排查假设，尚无崩溃证据证明根因。改为原地更新、固定层级及原生坐标绘制后，用户在 code.8 的短时检查中确认方向正常、CPU 弧线缺口未再出现。这不代表长期稳定、帧率上限已测得，或原来的偶发熄屏／断线已解决。验证范围见[测试与限制](../testing.md)。

## 静态底圈与原生绘制验证

任务聚合与有序配色仍由 App 负责。Buddy 0.5.11 虽降低了模型更新量，实机多任务测试仍发生重启，因此该方案本身不能视为已解决。

后续本地候选版将不变底圈与高光分开绑定。底圈使用官方 `style.static`；配色或页面改变时用新的 `tid` 重建，动画不修改底圈列表。动态元件每次提交完整样式，避免逐字段触发样式表达式；保留弧线原有底色；0.5.12 强制透明后用户报告外圈变形，0.5.13 撤回这项视觉改动。用户仍报告顶部直线偏细、接点异常；下一候选版将原生笔划统一为偶数像素，角色外圈和高光为 8 像素，使中心线与线帽半径均落在整数像素，资源笔划仍为 6 像素。共用原生预览同步采用该几何，接点测试新增中心线和线帽检查；此假设仍需实机确认。角色容器缩至图形实际边界，绝对坐标和原版动画保持一致，避免移动全屏透明容器。页面持有自己的角色数据副本，不增加图片、蓝牙动画帧或降低设置帧率。

回归检查覆盖静态节点更新、同值快照、完整样式坐标、角色坐标与边界和生命周期。1–6 色的 80 帧模型量测均为 520 次动态字段写入、底圈写入与元件替换为零；编译产物确认包含静态样式标记。这些不是原生内存、重绘区域或屏幕帧率量测，也不能证明重启原因；候选版仍需实机确认。参见[官方内存优化](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/memory.html)。官方组件目录不能证明该手环支持 Canvas，禁止直接假设网页 Canvas API 可用。

实机跟进：用户仍报告 0.5.14 顶部直线与曲线交接异常，偶数线宽未解决该缺陷。当前仅为未通过外观验收的本地候选版；继续调整几何前需要当前实机清晰照片作对照，不能将底色透明或奇数线宽当作已证实原因。

0.5.15 本地量测版保持这些外观参数，使用官方 `getBoundingClientRect` 在布局完成后比较画布与元件的请求／实际边界，只在静态节点更换或返回页面时读取。1 秒期限及代次检查处理无回覆或迟到回覆，隐藏和销毁时取消定时器。既有 ACK 诊断最多携带三个有界数值矩形及枚举状态，桌面健康记录使用白名单。边界不能证明光栅化线宽、半径语义或重启原因；不采集截图、提示词或设备标识。

实机 0.5.15 读回的画布 192×490、直线 8×157、弧线元件 186×186 及位置均与请求相符。参考像素测试另重现绘制顺序缺陷：统一先画直线后画弧线，使主笔划弧线覆盖接点的亮色尖端，静态弧线也可能盖住动态直线。0.5.16 将底圈、主笔划、尖端分为 0／1／2 层，整层顺序绘制；手环仅分组已有元件，Mac 预览同步，不改几何参数和帧率。测试检查思考／工作动画、上下接点、1–6 色、模板顺序及原地更新。软件不透明内部像素通过，不代表固件抗锯齿或实机稳定性已通过；仍需实机确认。三项量测可用时也读取完整胶囊边界，以核对不同元件的边框尺寸。


## 0.5.16 失败后的完整边框能力验证

0.5.16 实机仍重启，用户明确指出外层曲线错误；布局边界相符及尖端绘制顺序测试不能证明实际轮廓或稳定性。独立本地 `--capsule-border` 模板把两个完整原生胶囊边框放入固定尺寸、关闭双向滚动的视窗，仅取 App 编译的前两个真实任务颜色。通过依赖注入暂停角色动画，保留原控制器、过期／完成期限、连线及亮屏租约；正式入口不变，动画默认开启，预览跟随 `animationEnabled=false` 回执暂停。此实验替代继续猜线宽或半径。建置器才会选择模板、重定位其可检查的源导入，并仅提高临时包的 API level 2 与本地补丁版本，既有命令兼容。诊断仅允许枚举与数值。编译及 365 项软件测试不能证明本固件会正确裁切越界子元件；必须确认两段不同颜色及连续外曲线，才考虑采用这个后端。本控制版不验证最终动画、六色或长期稳定性。不增加启动图示外的图片、虚构任务事件、设置迁移或发布。

```sh
python3 scripts/build_band_probe.py --capsule-border --revision 1 --activate
npm run build:desktop -- --release --signing-mode local
```

启用时保留旧 RPK／元数据备份；之后运行 `npm run build` 会恢复正式源码包，打包本控制版时请保留已启用的原型包。


## 控制实验后恢复完整边框的 Loading 与呼吸

用户反馈 0.5.17 静态控制版的线条目测正常，并要求恢复呼吸与 Loading。这只提供完整外轮廓的视觉证据，尚未确认双色裁切与长时间稳定性。Buddy 0.5.18 的角色页使用完整原生边框，由共享代码生成矩形 scroll 视窗，划分主机准备的 1–6 种颜色。一个 RGBA 黑色边框统一调制呼吸，不逐个更新任务颜色。两个固定 Loading 主体和两个亮端各用两个裁切视窗，节点结构与每帧模型写入量不随任务数增加。各子边框始终是竖屏 184×482、宽 8 像素的完整胶囊。资源页、连接和亮屏租约保持原逻辑。

```sh
npm run build
npm run build:desktop -- --release --signing-mode local
```


实机跟进：用户反馈恢复后的效果可以，正在运行两个真实任务，暂未出现卡死或重启。App 预览也显示了双色外圈和 Loading。这只是初步短时间验证，不代表耐久测试通过或已验证六任务稳定性。
