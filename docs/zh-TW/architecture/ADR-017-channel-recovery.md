# ADR-017: 通道生命週期與分層恢復

[English](../../en/architecture/ADR-017-channel-recovery.md) · [简体中文](../../zh-CN/architecture/ADR-017-channel-recovery.md) · **繁體中文**

## 問題

系統藍牙仍連接時，Buddy 可能返回首頁，或 interconnect/RFCOMM 工作階段不再回應。後續 ACK 超時以前會覆蓋首次異常。

## 決定

Vela 負責建立通道。注入的手環控制器監聽 onopen/onclose/onerror，在建立及開啟時按能力呼叫 getReadyState，並設定一秒本地期限。只保留一份最新 ACK；關閉或錯誤後，下次開啟最多補送一次，重複開啟不會累積佇列。啟動時尚未就緒不算異常。銷毀會退役計時器、監聽器及回呼。可選 channelLifecycle 能力與 ACK 只攜帶有界計數、時間、列舉及數字錯誤碼，不攜帶平台原始錯誤文字。

Mac 在應用 ACK 缺失後立即探測裝置。探測成功只允許既有、有界且使用者已啟用的活動任務 Buddy 恢復，不重建傳輸。連續兩次探測失敗，或原生通道/子程序退出，才進入既有有界退避重連。應用、裝置探測、子程序恢復分別記錄；探測失敗本身不能證明實體藍牙斷開。暫停、任務結束、斷開、安裝及舊代回呼繼續遵守取消規則。

診斷在自動重連後保留首個觀測異常的主機時間、層級、安全錯誤碼及子程序代數，並僅補記一次原子程序退出碼／訊號。按能力接收的通道證據另保留手環本地首個事件時間與碼。後續成功或 ACK 超時不能覆蓋首次異常。明確連接操作開啟新的觀測視窗；runtime/App 重啟也會開啟新視窗。健康檔案逐欄位白名單投影。

首次 ACK 超時允許一次快速新快照重試；持續閒置失敗保留正常 30 秒投遞退避。第一次探測失敗後先給新快照回覆機會，再做第二次探測。探測請求 ID 唯一，遲到結果不能結算新的探測。明確使用者操作優先於背景探測。

## 替代方案

ACK 遺失就重設全部藍牙會打斷健康通道。虛構重連 API、週期性重開應用及偽造背景能力均不採用。將啟動建鏈算成異常會遮住真正的首個故障。

## 相容與證據

v1 協議及 session/seq 比對不變，無能力欄位的舊 ACK 繼續有效。快取 ACK 補送不會重新套用快照或延長亮屏租約。共享夾具、假時鐘生命週期／恢復測試及 Rust 投影測試涵蓋期限、舊回呼、隱私過濾及首因保留。編譯或 ACK 不能證明實物退出、重啟、長期掉線的原因或已解決。
