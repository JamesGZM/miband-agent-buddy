# ADR-007：明確的 Buddy 安裝清單

[English](ADR-007-band-installation-state.md) · [简体中文](ADR-007-band-installation-state.zh-CN.md) · **繁體中文**

狀態：已接受。日期：2026-11-11。

## 問題

無 ACK 可能是 Buddy 休眠、不可用或未安裝。原布爾預設值與通用安裝／更新控件不能區分，比較原始碼 manifest 也不能證明實際會安裝哪份 RPK。

## 決策

原生適配器讀取小米應用清單，只輸出 Buddy 是否存在及數字版本，不傳指紋、其他包名或安裝應用。桌面檢查帶明確 request ID，先喚醒並確認顯示，再有界查詢 `buddy_status`；若啟動發現缺包則直接確認未安裝。初始／安裝後啟動復用已讀取清單。暫停啟動和背景重連仍可只讀查詢；用戶手動檢查是獨立有界操作。

執行時增加 buddy 狀態：未知、檢查、缺失、已安裝、可更新、當前、新版、安裝中、錯誤。查詢失敗保留最後觀察，但不保證仍為當前版本。清單數字變化或確認缺失清除舊名稱並使進行中的舊 ACK 失效。匹配當前會話／序號的 ACK 名稱恰好等於隨包版本時，即使緩存數字舊，也可確認 current；保留原數字，不從名稱推斷數字。清單不變保留實時確認，數字更高仍為 newer；檢查完成前保持 checking。

明確安裝成功回執清除舊證據，獨立進行 install 喚醒／ACK，同步暫停也一樣。100% 僅證明傳輸，Core 最多等 120 秒安裝結果。`install_receipt_missing` 表示結果未確認，不保證安裝失敗；過期 waiter 清除。後來的新 ACK 或清單可獨立證明執行／安裝版本，不能把原缺失回執改成已收到成功。失敗或不確定也不代表舊 App 已刪除。

構建生成 `dist/buddy-package.json`，記錄名稱、數字版本和 SHA-256；執行時適配器驗證 RPK 位元組後才注入核心。元數據缺失或不匹配時不能比較版本。它描述隨桌面分發的包，不宣稱最新 GitHub 版本。

Buddy 狀態與更新屬於手環頁面，關於頁面桌面更新器獨立。

## 替代方案

- 無 ACK 不能當缺包，休眠也無回執。
- 清單數字支援睡眠時比較，不對版本名稱作全面排序；僅允許與已驗證隨包名稱精確相等的有限實時確認。
- 連線／安裝後重複查詢會阻塞串行原生操作和喚醒期限，因此復用已有請求。
- 不能執行時直接讀原始碼 manifest，生成包可能不同。

## 相容與證據

保留 installed 布爾、安裝命令、包身份及 RPK 路徑；check_buddy、buddy 事件和 state.buddy 是私有協議的可加字段。JavaScript／Rust 共用 fixture。測試覆蓋缺失、新舊版本、失敗／超時、拒絕安裝保留、安裝後驗證、靜默重連、舊傳輸、元數據不匹配、缺回執後名稱確認、重複及變化清單、舊 ACK、未知代碼與更高數字。原生測試確認只暴露存在性和版本碼。自動檢查不證明物理安裝或顯示。
