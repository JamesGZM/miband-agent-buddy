# ADR-007：明确的 Buddy 安装清单

[English](ADR-007-band-installation-state.md) · **简体中文** · [繁體中文](ADR-007-band-installation-state.zh-TW.md)

状态：已接受。日期：2026-11-11。

## 问题

无 ACK 可能是 Buddy 休眠、不可用或未安装。原布尔默认值与通用安装／更新控件不能区分，比较源码 manifest 也不能证明实际会安装哪份 RPK。

## 决策

原生适配器读取小米应用清单，只输出 Buddy 是否存在及数字版本，不传指纹、其他包名或安装应用。桌面检查带明确 request ID，先唤醒并确认显示，再有界查询 `buddy_status`；若启动发现缺包则直接确认未安装。初始／安装后启动复用已读取清单。暂停启动和后台重连仍可只读查询；用户手动检查是独立有界操作。

运行时增加 buddy 状态：未知、检查、缺失、已安装、可更新、当前、新版、安装中、错误。查询失败保留最后观察，但不保证仍为当前版本。清单数字变化或确认缺失清除旧名称并使进行中的旧 ACK 失效。匹配当前会话／序号的 ACK 名称恰好等于随包版本时，即使缓存数字旧，也可确认 current；保留原数字，不从名称推断数字。清单不变保留实时确认，数字更高仍为 newer；检查完成前保持 checking。

明确安装成功回执清除旧证据，独立进行 install 唤醒／ACK，同步暂停也一样。100% 仅证明传输，Core 最多等 120 秒安装结果。`install_receipt_missing` 表示结果未确认，不保证安装失败；过期 waiter 清除。后来的新 ACK 或清单可独立证明运行／安装版本，不能把原缺失回执改成已收到成功。失败或不确定也不代表旧 App 已删除。

构建生成 `dist/buddy-package.json`，记录名称、数字版本和 SHA-256；运行时适配器验证 RPK 字节后才注入核心。元数据缺失或不匹配时不能比较版本。它描述随桌面分发的包，不宣称最新 GitHub 版本。

Buddy 状态与更新属于手环页面，关于页面桌面更新器独立。

## 替代方案

- 无 ACK 不能当缺包，休眠也无回执。
- 清单数字支持睡眠时比较，不对版本名称作全面排序；仅允许与已验证随包名称精确相等的有限实时确认。
- 连接／安装后重复查询会阻塞串行原生操作和唤醒期限，因此复用已有请求。
- 不能运行时直接读源码 manifest，生成包可能不同。

## 兼容与证据

保留 installed 布尔、安装命令、包身份及 RPK 路径；check_buddy、buddy 事件和 state.buddy 是私有协议的可加字段。JavaScript／Rust 共用 fixture。测试覆盖缺失、新旧版本、失败／超时、拒绝安装保留、安装后验证、静默重连、旧传输、元数据不匹配、缺回执后名称确认、重复及变化清单、旧 ACK、未知代码与更高数字。原生测试确认只暴露存在性和版本码。自动检查不证明物理安装或显示。
