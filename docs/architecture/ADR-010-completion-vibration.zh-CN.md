# ADR-010：可选的任务完成震动

[English](ADR-010-completion-vibration.md) · **简体中文** · [繁體中文](ADR-010-completion-vibration.zh-TW.md)

## 问题与决策

每个 AI 任务完成时需要一次震动，即使其他会话仍在运行。整体显示模式变化不能证明哪个任务完成。

`completionVibration` 默认关闭，在 Mac 和手环持久化。`completionVibrationMode` 只允许 `short` 和 `long`，默认短震，关闭通知时保留模式选择。Mac 观察每个主会话从思考、执行或等待确认进入已接受的 `Stop` 完成事件。工具结束、等待确认、取消、会话清理和手动重置不计入。宿主必须提供真实生命周期 Hooks；不得从耗时、资源数值或事件缺失推测完成。

Mac 最多排队 128 个近期完成事件，未交付事件 60 秒过期，并以不含会话身份的通知编号批量携带次数。新版 Buddy 声明 `completionVibration` 能力后，运行时才发送设置及可选 `completion: {id, count}`。旧手环不收到这两个字段。开启开关不会补震关闭期间的历史事件。暂停、关闭开关、主动断开、重置及安装会清空队列。

手环验证载荷，等待设置持久化和页面可见，先保存最后接受的通知编号，再请求震动。匹配回执表示接受通知，不代表马达已实际震动；丢失 ACK 或页面重启不会重放当前交付。存储失败时保持安静。先保存再震动优先防止重复；保存后、物理效果前发生崩溃，可能丢失通知，不承诺物理效果恰好一次。

注入的适配器调用 `vibrator.vibrate({mode: selectedMode})`；短震请求间隔 600 毫秒，长震请求间隔 2000 毫秒。这是请求间隔，实际震动时长由手环系统决定。模式字段仅在发现 `completionVibrationModes` 能力后发送，修改需匹配持久化回执。隐藏、关闭开关及销毁会取消排队震动和定时器。沿用完成事件的唤醒策略进入前台，不增加周期后台拉起。官方 [Vela 震动文档](https://iot.mi.com/vela/quickapp/zh/features/system/vibrator.html)列出手环 9 支持 `vibrate`；该型号不支持的新 `start`／`stop` 接口不使用。manifest 声明 `system.vibrator`。

## 替代方案、兼容性与证据

根据整体 `complete` 触发会漏掉部分并行任务完成；每个 Stop 包或每帧触发会重复震动；假定新定时震动 API 可用缺少型号支持。紧凑编号／次数协议保留 v1、1024 字节限制、包标识和本地动画边界。

假时钟测试覆盖默认关闭与持久化、每个会话分别结束、同时完成次数、取消、回执丢失、重启去重、存储失败、定时器清理和旧手环。实际震感与间隔需要实机确认；接受回执仅证明软件接收，验证方式见[测试指南](../testing.zh-CN.md)。
