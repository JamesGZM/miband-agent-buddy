# ADR-008: 程式繪製 Buddy 動畫與任務環

[English](ADR-008-animation-and-task-rings.md) · [简体中文](ADR-008-animation-and-task-rings.zh-CN.md) · **繁體中文**

## 問題

點陣動畫幀使本地傳輸過大。原生繪圖實驗驗證了元件能力，但診斷畫面沒有保持已確認的 Buddy 設計。

## 決策

手環介面優先使用程式繪製並保留已確認設計。圖片例外、原始碼職責及驗證流程見[快應用介面指南](../development/quickapp-ui.zh-TW.md)。

目前幀率設定為 `buddyFps` 整數 10–30，預設 10；省電模式固定 10，並保留關閉後恢復的選擇。所有邊界驗證範圍，執行服務僅向聲明能力的 Buddy 發送，持久化回執匹配後才確認完成。預覽使用同一原生幾何、有效幀率與新鮮 ACK 的動畫時間；回報目標幀率不等於實測面板刷新率。照片中直線也出現雙線，因此將底軌隔離到固定背景 stack，防止新增子節點覆蓋進度線；使用者報告 code.7 已有改善，但這不能證明唯一的韌體根因。

正式頁面使用原生 div 矩形及弧形 progress 繪製原來的 490×192 佈局。`packages/buddy-shared/presentation/geometry.js` 統一定義三個角色、七像素膠囊外框、狀態顏色、載入高光、並行任務等分色段及三層資源膠囊。桌面 canvas 使用同一份幾何。資源標籤與數字保留原佈局。

保留 32 級呼吸、96 個載入位置、17 個中心位置及原週期；手環和桌面預覽共用 10–30 FPS 目標，預設 10，省電固定 10，不代表實測面板幀率。資源頁靜止後僅保留過期計時；隱藏、銷毀和停止均取消所屬工作。

產生器刪除已知的廢棄 capsule 輸出目錄，不再產生圖片幀。桌面只留三個主題縮圖；手環套件只有入口圖示一張圖片。圖示由確認的桌面母圖產生，192 像素資源內保留 160 像素圖形。一般及本地建置都稽核套件內圖片。本地建置器僅附加測試版本並備份舊套件，不再替換 UI。

## 資源頁後續

後續照片顯示雙線已有改善，但 CPU 弧線更新會留下累積缺口。根因尚未確認。圖形現改為先把共用橫向幾何投影到手環縱向座標，再綁定原生元件，取消圖形父容器的旋轉；文字保留原方向。測試驗證投影的座標、角度、進度及角色快取。在 Smart Band 9 NFC 韌體 3.1.32 的 code.8 短時檢查中，使用者確認方向正常、CPU 數值變化時缺口未再出現。這僅證明短時視覺改善，不代表長期穩定、面板幀率已測得或原來的熄屏／斷線已解決。幀率改為與秒數相同的數字輸入、儲存按鈕及 Enter 提交，範圍仍為 10–30，省電固定 10。

此前使用者認可角色頁，但資源接點仍異常。原生資源路徑改為固定直線與半圓，只在實際路徑端點加圓帽；弧形幾何固定，僅更新進度。兩像素底軌與六像素填充共用中心線，0–100% 保持固定 ID 和陣列長度。相同顯示值跳過幾何產生，ACK 與文字仍更新；數字節點僅在資源頁建立。測試涵蓋這些約束；短時視覺結果見上，裝置 heap／CPU 收益尚未測量。

## 替代方案

保留廢棄幀浪費傳輸時間；假設 Canvas 缺少韌體證據；獨立診斷角色改變已確認設計。採用已在裝置確認的原生元件和共用純幾何保留現有 UI。

## 相容性與證據

v1 協定、套件識別、偏好、手勢和亮屏租約不變。singleTask 頁面獨立管理控制器、通道和計時器；可選生命週期、繪圖及脫敏傳輸回執區分頁面隱藏、ACK 缺失和程序退出。

使用者在 Smart Band 9 NFC 韌體 3.1.32 確認原生幾何、圓弧動畫及新圖示。查詢 API 缺失表示未知。三次遠端前台啟動保持一個活動頁面；刻意注入的傳輸 SIGTERM 自動恢復。主動檢查應用列表期間的 ACK 間隙不證明自發藍牙故障。原來的偶發熄屏／斷線根因仍未確認；使用者最新明確表示目前未熄屏。

測試涵蓋幾何邊界、精確膠囊色段長度、所有主題狀態、姿態數量、插值、正常／省電節奏、重複刷新、清理及兩端產生模組一致性。建置與 ACK 不證明實機還原度、持續亮屏或電量表現。未獲授權發版。

## 實機失敗與有界原生更新

使用者報告 code.3 卡死並令手環重啟，此版實機驗證失敗。此前 ACK 與單元測試不代表穩定。報告前的診斷顯示資源頁、Buddy ACK 逾時、傳輸程序退出為零，不能據此確定韌體崩潰根因。

舊原型快取角色矩形，只以 10 Hz 改少量數值並使用一個弧形元件。code.3 以 30 Hz 替換兩個觀察陣列，工作角色頁最多八個弧形，典型資源頁九個。這違反官方[原地更新頁面物件](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/memory.html)及[減少動態樣式和重繪](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/business.html)的建議；渲染及觀察器壓力是有依據的假設，尚無崩潰堆疊證明。

修正保持觀察陣列及穩定色段 ID，僅寫變化欄位；角色幾何快取、整體位移；完整膠囊用單一邊框。目前目標預設 10 FPS，可選 10–30，省電固定 10；只有局部筆劃使用圓弧，單任務工作角色最多四個。資源插值與亮屏租約不變。測試涵蓋十五分鐘模擬動畫不替換陣列及一百次切頁；韌體記憶體、持續表現及不再重啟仍需耐久實測。

code.4 連續三分鐘的 19 次採樣保持同一頁面啟動標記、ACK 持續且無逾時；使用者報告兩頁曲線與直線接點異常。原生修正將中心線幾何轉換為 LVGL 外緣半徑，並將筆劃邊界與中心統一到整數像素。接點剖面測試先失敗後通過，檢查角色及資源線寬在兩個切點的內外邊界。公開 QuickApp 核心為預編譯程式庫，因此 LVGL 原始碼支持半徑假設，但不證明 Band 9 私有適配實作；實機視覺仍待確認。

## 靜態底圈與原生繪製驗證

任務聚合與有序配色仍由 App 負責。Buddy 0.5.11 雖降低了模型更新量，實機多任務測試仍發生重啟，因此該方案本身不能視為已解決。

後續本地候選版將不變底圈與高光分開綁定。底圈使用官方 `style.static`；配色或頁面改變時用新的 `tid` 重建，動畫不修改底圈列表。動態元件每次提交完整樣式，避免逐欄位觸發樣式運算式；保留弧線原有底色；0.5.12 強制透明後使用者回報外圈變形，0.5.13 撤回這項視覺改動。使用者仍回報頂部直線偏細、接點異常；下一候選版將原生筆劃統一為偶數像素，角色外圈和高光為 8 像素，使中心線與線帽半徑均落在整數像素，資源筆劃仍為 6 像素。共用原生預覽同步採用該幾何，接點測試新增中心線和線帽檢查；此假設仍需實機確認。角色容器縮至圖形實際邊界，絕對座標和原版動畫保持一致，避免移動全螢幕透明容器。頁面持有自己的角色資料副本，不增加圖片、藍牙動畫幀或降低設定幀率。

回歸檢查涵蓋靜態節點更新、同值快照、完整樣式座標、角色座標與邊界及生命週期。1–6 色的 80 幀模型量測均為 520 次動態欄位寫入、底圈寫入與元件替換為零；編譯產物確認包含靜態樣式標記。這些不是原生記憶體、重繪區域或螢幕幀率量測，也不能證明重啟原因；候選版仍需實機確認。參見[官方記憶體優化](https://iot.mi.com/vela/quickapp/zh/guide/best-practice/memory.html)。官方元件目錄不能證明該手環支援 Canvas，禁止直接假設網頁 Canvas API 可用。

實機跟進：使用者仍回報 0.5.14 頂部直線與曲線交接異常，偶數線寬未解決該缺陷。目前僅為未通過外觀驗收的本地候選版；繼續調整幾何前需要目前實機清晰照片作對照，不能將底色透明或奇數線寬當作已證實原因。

0.5.15 本地量測版保持這些外觀參數，使用官方 `getBoundingClientRect` 在佈局完成後比較畫布與元件的請求／實際邊界，只在靜態節點更換或返回頁面時讀取。1 秒期限及代次檢查處理無回覆或遲到回覆，隱藏和銷毀時取消計時器。既有 ACK 診斷最多攜帶三個有界數值矩形及列舉狀態，桌面健康記錄使用白名單。邊界不能證明光柵化線寬、半徑語義或重啟原因；不蒐集截圖、提示詞或裝置識別碼。

實機 0.5.15 讀回的畫布 192×490、直線 8×157、弧線元件 186×186 及位置均與請求相符。參考像素測試另重現繪製順序缺陷：統一先畫直線後畫弧線，使主筆劃弧線覆蓋接點的亮色尖端，靜態弧線也可能蓋住動態直線。0.5.16 將底圈、主筆劃、尖端分為 0／1／2 層，整層依序繪製；手環僅分組既有元件，Mac 預覽同步，不改幾何參數和幀率。測試檢查思考／工作動畫、上下接點、1–6 色、模板順序及原地更新。軟體不透明內部像素通過，不代表韌體反鋸齒或實機穩定性已通過；仍需實機確認。三項量測可用時也讀取完整膠囊邊界，以核對不同元件的邊框尺寸。


## 0.5.16 失敗後的完整邊框能力驗證

0.5.16 實機仍重啟，使用者明確指出外層曲線錯誤；佈局邊界相符及尖端繪製順序測試不能證明實際輪廓或穩定性。獨立本地 `--capsule-border` 模板把兩個完整原生膠囊邊框放入固定尺寸、關閉雙向捲動的視窗，僅取 App 編譯的前兩個真實任務顏色。透過依賴注入暫停角色動畫，保留原控制器、過期／完成期限、連線及亮屏租約；正式入口不變，動畫預設開啟，預覽跟隨 `animationEnabled=false` 回執暫停。此實驗替代繼續猜線寬或半徑。建置器才會選擇模板、重定位其可檢查的源匯入，並僅提高臨時包的 API level 2 與本地修補版本，既有命令相容。診斷僅允許列舉與數值。編譯及 365 項軟體測試不能證明本韌體會正確裁切越界子元件；必須確認兩段不同顏色及連續外曲線，才考慮採用這個後端。本控制版不驗證最終動畫、六色或長期穩定性。不增加啟動圖示外的圖片、虛構任務事件、設定遷移或發布。

```sh
python3 scripts/build_band_probe.py --capsule-border --revision 1 --activate
npm run build:desktop -- --release --signing-mode local
```

啟用時保留舊 RPK／中繼資料備份；之後執行 `npm run build` 會恢復正式原始碼包，打包本控制版時請保留已啟用的原型包。


## 控制實驗後恢復完整邊框的 Loading 與呼吸

使用者回饋 0.5.17 靜態控制版的線條目測正常，並要求恢復呼吸與 Loading。這只提供完整外輪廓的視覺證據，尚未確認雙色裁切與長時間穩定性。Buddy 0.5.18 的角色頁使用完整原生邊框，由共享程式產生矩形 scroll 視窗，劃分主機準備的 1–6 種顏色。一個 RGBA 黑色邊框統一調制呼吸，不逐個更新任務顏色。兩個固定 Loading 主體和兩個亮端各用兩個裁切視窗，節點結構與每幀模型寫入量不隨任務數增加。各子邊框始終是直向 184×482、寬 8 像素的完整膠囊。資源頁、連線和亮屏租約維持原邏輯。

恢復分段 progress 弧線會重新使用尚未通過實機驗收的輪廓實作；逐顏色呼吸則會讓響應式更新量隨任務數增加。共享幾何為手環和有新鮮回執的 App 預覽提供相同視窗、呼吸相位、角色姿態和 Loading 顏色。此實作需要官方 API Level 2 的 scroll 元件；套件身分、偏好和協定 v1 保持相容。RPK 仍僅含啟動圖示一張圖片。測試涵蓋邊框像素完整且不重疊、固定 Loading 節點、座標投影、呼吸、與任務數無關的模型更新、銷毀和預覽重建。這些模型斷言不代表韌體記憶體/CPU 測量、真實裁切/光柵正確或已解決重啟；實機動畫與耐久驗收仍待完成，不發布。


實機跟進：使用者回饋恢復後的效果可以，正在執行兩個真實任務，暫未出現卡死或重啟。App 預覽也顯示了雙色外圈和 Loading。這只是初步短時間驗證，不代表耐久測試通過或已驗證六任務穩定性。
