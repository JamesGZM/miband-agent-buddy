# ADR-010：可選的任務完成震動

[English](ADR-010-completion-vibration.md) · [简体中文](ADR-010-completion-vibration.zh-CN.md) · **繁體中文**

## 問題與決策

每個 AI 任務完成時需要一次震動，即使其他會話仍在執行。整體顯示模式變化不能證明哪個任務完成。

`completionVibration` 預設關閉，在 Mac 和手環持久化。`completionVibrationMode` 只允許 `short` 和 `long`，預設短震，關閉通知時保留模式選擇。Mac 觀察每個主會話從思考、執行或等待確認進入已接受的 `Stop` 完成事件。工具結束、等待確認、取消、會話清理和手動重設不計入。宿主必須提供真實生命週期 Hooks；不得從耗時、資源數值或事件缺失推測完成。

Mac 最多排隊 128 個近期完成事件，未交付事件 60 秒過期，並以不含會話身分的通知編號批次攜帶次數。新版 Buddy 宣告 `completionVibration` 能力後，執行服務才發送設定及可選 `completion: {id, count}`。舊手環不收到這兩個欄位。開啟開關不會補震關閉期間的歷史事件。暫停、關閉開關、主動斷開、重設及安裝會清空佇列。

手環驗證載荷，等待設定持久化和頁面可見，先儲存最後接受的通知編號，再請求震動。匹配回執表示接受通知，不代表馬達已實際震動；丟失 ACK 或頁面重啟不會重放目前交付。儲存失敗時保持安靜。先儲存再震動優先防止重複；儲存後、物理效果前發生崩潰，可能丟失通知，不承諾物理效果恰好一次。

注入的適配器呼叫 `vibrator.vibrate({mode: selectedMode})`；短震請求間隔 600 毫秒，長震請求間隔 2000 毫秒。這是請求間隔，實際震動時長由手環系統決定。模式欄位僅在發現 `completionVibrationModes` 能力後發送，修改需匹配持久化回執。隱藏、關閉開關及銷毀會取消排隊震動和計時器。沿用完成事件的喚醒策略進入前台，不增加週期背景拉起。官方 [Vela 震動文件](https://iot.mi.com/vela/quickapp/zh/features/system/vibrator.html)列出手環 9 支援 `vibrate`；該型號不支援的新 `start`／`stop` 介面不使用。manifest 宣告 `system.vibrator`。

## 替代方案、相容性與證據

根據整體 `complete` 觸發會漏掉部分並行任務完成；每個 Stop 封包或每幀觸發會重複震動；假定新定時震動 API 可用缺少型號支援。緊湊編號／次數協定保留 v1、1024 位元組限制、套件識別和本地動畫邊界。

假時鐘測試涵蓋預設關閉與持久化、每個會話分別結束、同時完成次數、取消、回執丟失、重啟去重、儲存失敗、計時器清理和舊手環。實際震感與間隔需要實機確認；接受回執僅證明軟體接收，驗證方式見[測試指南](../testing.zh-TW.md)。
