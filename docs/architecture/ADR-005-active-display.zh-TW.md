# ADR-005：活動任務期間保持亮屏

[English](ADR-005-active-display.md) · [简体中文](ADR-005-active-display.zh-CN.md) · **繁體中文**

## 問題

一次性租約可能在 AI 思考、調用工具或等待權限時到期。每份指標都延長普通租約會阻止空閒息屏，主機異常後也可能持續耗電。一個任務結束不能遮蔽併發任務。

## 決策

`activityKeepAwake` 持久化且預設 false，舊配置升級也一樣。類型化 `activity_keep_awake` 保存並立即更新執行時，無需重連。關閉時，事件與手動喚醒仍使用有界單次租約。

每次明確設定操作在鏈路可用時喚醒一次，無論重複值或開關方向；顯示喚醒／應用／結果，並等待匹配回執。普通配置不發起額外啟動。斷線或安裝中只保存意圖。同步暫停仍允許手動有界交易，但不續期任務或恢復背景同步；恢復同步且任務仍活動時喚醒一次。

`syncEnabled` 預設 true，視窗和選單列持久化同一狀態，啟動先恢復暫停再自動連線，避免關閉同步後重啟短暫發送。

傳輸重連認證後，只有同步開啟、任務亮屏開啟且任務仍活動時，請求一次 `activity_reconnect` 喚醒，不需要新的 Hook。認證及實際傳送前均檢查最新任務與設定，排隊期間取消會丟棄恢復請求；重複認證被忽略。空閒、已結束、暫停或關閉時不啟動。它替代了無條件安靜重連，修復活動任務斷鏈後一直黑屏；不是週期重開，仍受冷卻與喚醒／ACK 期限限制。

Buddy 0.5.4 聲明 `capabilities.activityHold=true`，執行時在匹配 ACK 觀察到能力後才發送成對 v1 字段 `activityHoldMs` 與 `idleHoldMs`。啟用且 activeSessions 非零時前者為 15,000 ms，否則為零；後者為保存的 5–1800 秒待機寬限。關閉亮屏只啟動一次寬限，不清除任務。聚合活動優先於單個會話的完成動畫。

手環每份有效活動快照續期 15 秒本地看門狗。成功亮度請求每 30 秒刷新，失敗或回調超時後兩秒重試，success 中負的 native value 也算失敗。兩秒普通快照只移動期限。首次活動轉空閒時啟動一次待機寬限，後續空閒快照不延期；活動中的手動喚醒保留看門狗，不替換為長待機租約。

資源採樣不控制任務傳輸，最多一個採樣工作。數據最多沿用兩個採樣間隔，之後顯示未知，採樣異常或檔案系統卡住仍發送活動與終止快照；停止後遲到結果不能恢復執行。它替代每次發送前等待完整採樣；不使用重疊重試，以免檔案系統卡住時堆積工作。

斷線、暫停、安裝或關閉導致快照停止時，本地看門狗到期釋放。hide／exit／destroy 取消定時器並使舊回調失效，重複快照不能續期。重新顯示需新快照，緩存活動不會自行恢復。`wakeDisplay.active` 表示活動租約，`remainingMs` 是看門狗而非用戶待機時長。

15 分鐘無事件後標記 stale，並暴露 freshActiveSessions／staleSessions；這只是警告，長工具或思考可數小時無事件，終止事件或明確重置前仍保持活動與續期。部分客戶端取消時不發終止事件，例如某些 Claude Code Escape；不能用時間猜測真實任務已結束。

`reset_activity` 清除會話及排隊／進行中的 Hook 喚醒，保留歷史計數。桌面帶 request ID 的重置即使暫停也喚醒一次、等待顯示回執；舊的不帶 ID 命令仍只清本地。不取消或授權 AI 工作。

## 充電畫面與短暫狀態查詢失敗

一次裝置狀態探測失敗不足以證明藍牙已經中斷。第一次失敗或逾時保留傳輸程序，5 秒後重試；連續兩次失敗仍會觸發恢復。匹配 Buddy ACK 會取消待完成探測並忽略其晚到失敗；有效電量／裝置狀態或 Buddy ACK 會重設失敗計數。

充電從否變為是時，如果同步及任務保持亮屏已開啟、任務仍活躍，且本次連線中曾顯示 Buddy（充電隱藏後的 ACK 不會抹掉此前的顯示狀態），則在 2 秒緩衝後請求一次恢復。初始或重複充電採樣不重新啟動 Buddy。暫停、重設任務、關閉保持亮屏、拔下充電器、中斷或安裝都會取消待恢復請求；啟動前仍檢查傳輸代次及任務和設定。普通電量採樣不會週期性重開 Buddy。

## 回執轉送與活動重試

問題：在事件接收分支等待慢速原生命令會扣留 Buddy ACK；漏回執後又等待 30 秒，超過 15 秒活動看門狗。

決策：保留一個循序命令 Future，同時驅動事件接收。所有者退出時先取消命令再清理裝置，不留下背景工作。三種獨立資訊查詢在原有五秒期限內並行執行，移除迴圈前重複電量查詢。後續喚醒複用本次工作階段的應用資訊，安裝會使準備狀態失效；使用固定脫敏錯誤碼區分清單、同步與啟動階段。開啟任務亮屏且任務活動時兩秒後重試傳送；空閒、暫停、關閉開關時保留舊退避。standby 與過期亮屏回執顯示待確認，不推斷物理休眠。

保留阻塞分支或週期重開 Buddy 會繼續觸發逾時，或干擾使用者導覽。目前決策保留命令順序、協定 v1 和有界手動喚醒。假時鐘測試重現漏回執並驗證在看門狗到期前恢復且沒有額外啟動；原生測試驗證慢命令期間 ACK 轉送和所有者退出取消。實際持續亮屏仍需實機驗證。

自有 SPP 適配層把底層最終開啟失敗／通道關閉轉換為工作階段訊號，不再忽略。連線嘗試和活動事件泵收到後立即取消待處理工作，使用固定 `bluetooth_open_failed`／`bluetooth_link_closed` 錯誤碼；原始底層詳情不進入診斷。不改動固定版本的主執行緒傳輸實作。

## 對未回應的活動 Buddy 恢復一次喚醒

藍牙通道仍正常時，Buddy 頁面也可能已無法接收快照。應用 ACK 逾時後，開啟任務亮屏且仍有任務時繼續快速重試；目前通道探測成功後，等待兩秒讓重試 ACK 先到達。若 Buddy 仍未回應、上次確認在前景且支援任務保活，則透過既有冷卻、TTL 和 15 秒確認期限請求一次 `activity_unresponsive` 喚醒。正常 ACK 會取消等待／排隊的恢復。只有前景且保持亮屏的回執才能重新啟用下一次獨立中斷的恢復；同一次中斷中的重複探測和逾時不會反覆啟動。

探測失敗／無回執、任務空閒、同步暫停、關閉任務亮屏或已確認頁面隱藏時不觸發。手動操作和任務事件保留優先權。任務結束／重置、關閉開關、暫停、斷線、安裝和更換連線所有者會取消待恢復工作，實際啟動前再次檢查條件。這替代無法接收快照時的被動等待，保留協定 v1，不新增週期重開。假時鐘測試涵蓋恢復確認、短暫漏回執、冷卻取消、單次嘗試、重新啟用及所有者／設定／任務取消；實際顯示仍需按驗證指南實機確認。

任務結束或策略／所有者變更也會廢棄已送出恢復的喚醒 ID，遲到的原生啟動結果不能再建立亮屏租約。

## 替代方案

- 永久亮屏無法在主機失效後本地恢復。
- 每份指標延長長租約會妨礙息屏並放大斷線耗電。
- 定時重新啟動會干擾用戶導航，正常會話不使用該策略。

## 相容

v1、`keepScreen=false`、唯一 wake ID、數據路徑和事件策略不變；舊版保留單次租約，每次連線重新協商能力。Rust 保留可加字段，桌面與手環版本獨立。

支援能力的快照還可帶 `sessionCounts`，思考／執行／等待均為非負整數，總計最多 128，與亮屏開關獨立。純共享顯示函數把併發數映射到原有圓環內最多六色，不增加文字。顏色不代表 provider，也不包含任務名、會話 ID 或內容；過期或空閒恢復原環。

## 證據

界面參考 [Code Light AI](https://github.com/cuihp/code-light-ai) 的聚合優先級與併發顯示，以及 [AgentHUD](https://github.com/garunnir/AgentHUD) 的緊湊狀態。Buddy 只用手選角色與原圓環顏色適配小屏，不複製原始碼、圖像或讀取對話的實現。

假時鐘覆蓋預設關閉、手動雙向操作、暫停與啟動、八小時無新 Hook、聚合、單次寬限、過期警告、重置回執、斷線／暫停過期、重複包、舊回調、隱藏頁及舊版能力；新增採樣異常／卡住、負值 success、快速重試與活動重連恢復。Rust 驗證舊配置、持久化和 UI 投影，共享 fixture 驗證邊界。物理亮屏仍需設備觀察，ACK 不構成證明。

## 啟動準備失敗後的恢復

重連可能在真正送出啟動前就因應用清單／狀態查詢失敗。隨後快照能夠刷新原生應用中繼資料，卻不會開啟 Buddy；舊 ACK 與能力也屬於已廢棄的傳輸連線。因此，開啟任務保持亮屏且仍有任務時，保留 60 秒、最多兩次重試的恢復意圖。必須有本連線的新安裝清單與成功鏈路探測，遵守現有啟動冷卻與確認時限。僅固定的 `app_query_failed` / `app_sync_failed` 可授權重試；沒有結果、啟動失敗或應用不存在均不能授權。成功入列後結束此意圖，仍需 Buddy 亮屏回執。正常 ACK、手動操作、任務結束／重設、暫停、關閉保持亮屏、安裝與連線歸屬變化取消排隊，晚到結果不能建立亮屏租約。首次背景裝置查詢延至首次 Buddy 喚醒確認後，優先建立亮屏租約。假時鐘測試覆蓋已重現的重連失敗、次數上限、探測／清單條件、查詢順序及取消；仍需持續執行的實機驗證。
