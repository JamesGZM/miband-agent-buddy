# ADR-005：活动任务期间保持亮屏

[English](ADR-005-active-display.md) · **简体中文** · [繁體中文](ADR-005-active-display.zh-TW.md)

## 问题

一次性租约可能在 AI 思考、调用工具或等待权限时到期。每份指标都延长普通租约会阻止空闲息屏，主机异常后也可能持续耗电。一个任务结束不能遮蔽并发任务。

## 决策

`activityKeepAwake` 持久化且默认 false，旧配置升级也一样。类型化 `activity_keep_awake` 保存并立即更新运行时，无需重连。关闭时，事件与手动唤醒仍使用有界单次租约。

每次明确设置操作在链路可用时唤醒一次，无论重复值或开关方向；显示唤醒／应用／结果，并等待匹配回执。普通配置不发起额外启动。断线或安装中只保存意图。同步暂停仍允许手动有界交易，但不续期任务或恢复背景同步；恢复同步且任务仍活动时唤醒一次。

`syncEnabled` 默认 true，窗口和托盘持久化同一状态，启动先恢复暂停再自动连接，避免关闭同步后重启短暂发送。

传输重连认证后，只有同步开启、任务亮屏开启且任务仍活动时恢复传输，不需要新的 Hook。先前确认的前台活动租约若声明 `activityHold=true` 且整数 `maxActivityHoldMs>=120000`，先发快照并等待最多一个 ACK 时限；新的前台活动回执或隐藏页回执取消兜底，没有确认回执才请求一次有界 `activity_reconnect` 唤醒。其他能力保留立即恢复唤醒策略。认证及实际发送前均检查最新任务与设置，排队期间取消会丢弃恢复请求；重复认证被忽略。空闲、已结束、暂停或关闭时不启动。它不是周期重开，仍受冷却与唤醒／ACK 期限限制。

Buddy 0.5.4 声明 `capabilities.activityHold=true`，运行时在匹配 ACK 观察到能力后才发送成对 v1 字段 `activityHoldMs` 与 `idleHoldMs`。启用且 activeSessions 非零时，前者取 120,000 ms 与声明的整数 `maxActivityHoldMs>=1000` 中较小者；上限缺失或无效时保留旧版 15,000 ms。未启用或没有活动会话时为零。后者为保存的 5–1800 秒待机宽限。关闭亮屏只启动一次宽限，不清除任务。聚合活动优先于单个会话的完成动画。

手环按每份有效活动快照的 `activityHoldMs` 续期本地看门狗，上限 120,000 ms。成功亮度请求每 30 秒刷新，失败或回调超时后两秒重试，success 中负的 native value 也算失败。两秒普通快照只移动期限。首次活动转空闲时启动一次待机宽限，后续空闲快照不延期；活动中的手动唤醒保留看门狗，不替换为长待机租约。

资源采样不控制任务传输，最多一个采样工作。数据最多沿用两个采样间隔，之后显示未知，采样异常或文件系统卡住仍发送活动与终止快照；停止后迟到结果不能恢复运行。它替代每次发送前等待完整采样；不使用重叠重试，以免文件系统卡住时堆积工作。

断线、暂停、安装或关闭导致快照停止时，本地看门狗到期释放。hide／exit／destroy 取消定时器并使旧回调失效，重复快照不能续期。重新显示需新快照，缓存活动不会自行恢复。`wakeDisplay.active` 表示活动租约，`remainingMs` 是看门狗而非用户待机时长。

15 分钟无事件后标记 stale，并暴露 freshActiveSessions／staleSessions；这只是警告，长工具或思考可数小时无事件，终止事件或明确重置前仍保持活动与续期。部分客户端取消时不发终止事件，例如某些 Claude Code Escape；不能用时间猜测真实任务已结束。

`reset_activity` 清除会话及排队／进行中的 Hook 唤醒，保留历史计数。桌面带 request ID 的重置即使暂停也唤醒一次、等待显示回执；旧的不带 ID 命令仍只清本地。不取消或授权 AI 工作。

## 充电画面与短暂状态查询失败

一次设备状态探测失败不足以证明蓝牙已经断开。第一次失败或超时保留传输进程，5 秒后重试；连续两次失败仍会触发恢复。匹配 Buddy ACK 会取消待完成探测并忽略其晚到失败；有效电量／设备状态或 Buddy ACK 会重置失败计数。

充电从否变为是时，如果同步及任务保持亮屏已开启、任务仍活跃，且本次连接中曾显示 Buddy（充电隐藏后的 ACK 不会抹掉此前的显示状态），则在 2 秒缓冲后请求一次恢复。初始或重复充电采样不重新启动 Buddy。暂停、重置任务、关闭保持亮屏、拔下充电器、断开或安装都会取消待恢复请求；启动前仍检查传输代次及任务和设置。普通电量采样不会周期性重开 Buddy。

## 回执转发与活动重试

问题：在事件接收分支等待慢速原生命令会扣留 Buddy ACK；漏回执后又等待 30 秒，超过 15 秒活动看门狗。

决策：保留一个串行命令 Future，同时驱动事件接收。所有者退出时先取消命令再清理设备，不留下后台任务。三种独立信息查询在原有五秒期限内并发执行，移除循环前重复电量查询。后续唤醒复用本次会话的应用信息，安装会使准备状态失效；使用固定脱敏错误码区分清单、同步与启动阶段。开启任务亮屏且任务活动时两秒后重试传送；空闲、暂停、关闭开关时保留旧退避。standby 与过期亮屏回执显示待确认，不推断物理休眠。

保留阻塞分支或周期重开 Buddy 会继续触发超时，或干扰用户导航。当前决策保留命令顺序、协议 v1 和有界手动唤醒。假时钟测试复现漏回执并验证在看门狗到期前恢复且没有额外启动；原生测试验证慢命令期间 ACK 转发和所有者退出取消。实际持续亮屏仍需实机验证。

自有 SPP 适配层把底层最终打开失败／通道关闭转换为会话信号，不再忽略。连接尝试和活动事件泵收到后立即取消待处理工作，使用固定 `bluetooth_open_failed`／`bluetooth_link_closed` 错误码；原始底层详情不进入诊断。不改动固定版本的主线程传输实现。

## 对未响应的活动 Buddy 恢复一次唤醒

蓝牙通道仍正常时，Buddy 页面也可能已无法接收快照。应用 ACK 超时后，开启任务亮屏且仍有任务时继续快速重试；当前通道探测成功后，等待两秒让重试 ACK 先到达。若 Buddy 仍未响应、上次确认在前台且支持任务保活，则通过既有冷却、TTL 和 15 秒确认期限请求一次 `activity_unresponsive` 唤醒。正常 ACK 会取消等待／排队的恢复。只有前台且保持亮屏的回执才能重新启用下一次独立中断的恢复；同一次中断中的重复探测和超时不会反复启动。

探测失败／无回执、任务空闲、同步暂停、关闭任务亮屏或已确认页面隐藏时不触发。手动操作和任务事件保留优先级。任务结束／重置、关闭开关、暂停、断线、安装和更换连接所有者会取消待恢复工作，实际启动前再次检查条件。这替代无法接收快照时的被动等待，保留协议 v1，不添加周期重开。假时钟测试覆盖恢复确认、短暂漏回执、冷却取消、单次尝试、重新启用及所有者／设置／任务取消；实际显示仍需按验证指南实机确认。

任务结束或策略／所有者变化也会废弃已发出恢复的唤醒 ID，迟到的原生启动结果不能再建立亮屏租约。

## 替代方案

- 永久亮屏无法在主机失效后本地恢复。
- 每份指标延长长租约会妨碍息屏并放大断线耗电。
- 定时重新启动会干扰用户导航，正常会话不使用该策略。

## 兼容

v1、`keepScreen=false`、唯一 wake ID、数据路径和事件策略不变；旧版保留单次租约，每次连接重新协商能力。Rust 保留可加字段，桌面与手环版本独立。

支持能力的快照还可带 `sessionCounts`，思考／执行／等待均为非负整数，总计最多 128，与亮屏开关独立。纯共享显示函数把并发数映射到原有圆环内最多六色，不增加文字。颜色不代表 provider，也不包含任务名、会话 ID 或内容；过期或空闲恢复原环。

## 证据

界面参考 [Code Light AI](https://github.com/cuihp/code-light-ai) 的聚合优先级与并发显示，以及 [AgentHUD](https://github.com/garunnir/AgentHUD) 的紧凑状态。Buddy 只用手选角色与原圆环颜色适配小屏，不复制源码、图像或读取对话的实现。

假时钟覆盖默认关闭、手动双向操作、暂停与启动、八小时无新 Hook、聚合、单次宽限、过期警告、重置回执、断线／暂停过期、重复包、旧回调、隐藏页及旧版能力；新增采样异常／卡住、负值 success、快速重试与活动重连恢复。Rust 验证旧配置、持久化和 UI 投影，共享 fixture 验证边界。物理亮屏仍需设备观察，ACK 不构成证明。

## 启动准备失败后的恢复

重连可能在真正发送启动前就因应用清单／状态查询失败。随后快照能够刷新原生应用元数据，却不会打开 Buddy；旧 ACK 与能力也属于已废弃的传输连接。因此，开启任务保持亮屏且仍有任务时，保留 60 秒、最多两次重试的恢复意图。必须有本连接的新安装清单与成功链路探测，遵守现有启动冷却与确认时限。仅固定的 `app_query_failed` / `app_sync_failed` 可授权重试；没有结果、启动失败或应用不存在均不能授权。成功入队后结束此意图，仍需 Buddy 亮屏回执。正常 ACK、手动操作、任务结束／重设、暂停、关闭保持亮屏、安装与连接归属变化取消排队，晚到结果不能创建亮屏租约。首次后台设备查询延至首次 Buddy 唤醒确认后，优先建立亮屏租约。假时钟测试覆盖已重现的重连失败、次数上限、探测／清单条件、查询顺序及取消；仍需持续运行的实机验证。

## 任务中的短暂断线

租约协商与重连桥接使用不同门槛：有效的 60,000 ms 上限会协商出 60 秒租约，但只有先前确认的前台活动回执声明 `activityHold=true` 且整数上限至少为 120,000 ms，才启用先发快照的重连。更短或旧版能力保留立即有界恢复唤醒。

Buddy 0.5.11 宣告 `maxActivityHoldMs=120000`，Mac 将活动亮屏期限限制在此上限；未宣告或无效时保留旧版 15 秒。页面仍可见时，在有限的通信间隙保留最近的活动任务画面。明确的非活动快照立即启动原有待机倒数；隐藏、返回或销毁取消所有保持。两分钟没有续期仍释放亮屏。重连时，对先前确认支持缓冲的画面先发送新快照，等待最多一个 ACK 时限；活动亮屏回执取消启动兜底，隐藏页回执尊重隐藏状态，无回覆才使用现有有界唤醒。新认证连接的首次清单不能丢弃本连接首个待确认快照；已知安装版本变化仍使旧回执失效。假时钟覆盖 45 秒断线、两分钟上限、明确结束后倒数、旧版协商、先同步重连及取消。合并版本仍待实机验证。
